## 1. Справка

### 1.1. Постановка

Граф — свободные клетки сетки с рёбрами к четырём соседям. У каждого из k агентов старт sᵢ и цель gᵢ. Время дискретно: за шаг агент переходит в соседнюю клетку или ждёт. После прибытия агент **стоит на цели бесконечно**. Запрещены:

- **вершинный конфликт** — два агента в одной клетке в один момент;
- **рёберный конфликт (обмен местами)** — агенты a и b за один шаг меняются клетками.

**Следование** (a входит в клетку, которую b покидает на этом же шаге) в классической постановке разрешено. Критерий — **сумма стоимостей**: сумма моментов прибытия (после которых агент уже не двигается). Задача NP-трудна при оптимизации суммы стоимостей.

### 1.2. A* в пространстве-времени

Состояние — пара (клетка, t). Переходы — в соседние клетки и ожидание, каждый стоит 1. Ограничения ('v', клетка, t) и ('e', откуда, куда, t) вычёркивают переходы. Эвристика — манхэттенское расстояние (допустима: ожидание только удлиняет путь).

**Тонкость цели.** Агент в клетке цели в момент t ещё не «прибыл», если на цель наложено ограничение в какой-либо момент t′ ≥ t: он не сможет там стоять. Поэтому условие достижения — «клетка = цель и t больше последнего момента, в который цель запрещена». Без этого CBS зацикливается: агент паркуется на цели, его выгоняют ограничением, он паркуется снова раньше.

**Горизонт.** Если ограничения запрещают прибытие навсегда, поиск в бесконечном времени не остановится. Горизонт max_t: по умолчанию — число клеток плюс наибольший момент в ограничениях.

### 1.3. Приоритетное планирование

Агенты планируют по очереди; каждый считает пути предыдущих движущимися препятствиями: вершинные ограничения на каждый момент (включая бесконечную стоянку на цели до горизонта) и запрет обмена. Быстро, но **не полно**: агент с высоким приоритетом может занять клетку, без которой младший не пройдёт.

### 1.4. CBS

Двухуровневый поиск. **Верхний уровень** — дерево ограничений; узел содержит ограничения для каждого агента, пути, удовлетворяющие ограничениям, и стоимость. Корень — кратчайшие пути без ограничений. Раскрываем узел с наименьшей стоимостью; ищем первый конфликт; если его нет — решение оптимально. Иначе — два потомка: в одном ограничение получает первый агент конфликта, в другом — второй; перепланируется **только** агент, получивший ограничение.

Оптимальность: стоимость потомков не меньше стоимости родителя (ограничения только добавляются), а любое допустимое решение удовлетворяет хотя бы одному из двух ограничений каждого разбиения. Полнота — при неограниченном числе узлов; число узлов растёт экспоненциально с числом конфликтов.

### 1.5. Разрыв «план — исполнение» и граф зависимостей

План рассчитан на идеальные часы. Реальный робот буксует, ждёт манипулятор, пропускает человека — и опаздывает. Если остальные продолжают «по часам», вершинные конфликты плана появляются в исполнении.

**Граф зависимостей действий** (упрощённый ADG, Hönig и др., 2019). Сожмите путь в последовательность переходов (ожидания выбросить). Если агент j по плану находится в клетке c раньше, чем туда входит агент i, то действие i «войти в c» зависит от действия j «выйти из c». Исполнитель выполняет действие, только когда все его зависимости выполнены. Порядок посещения каждой клетки сохраняется, поэтому двух агентов в одной клетке не бывает **при любых задержках**. Цена — ожидания: задержка одного робота каскадом задерживает зависящих от него.

## 3. Базовый маршрут

### Шаг 1. A* в пространстве-времени

Реализуйте `space_time_astar`. Рекомендуемая структура:

- очередь `heapq` из кортежей `(f, g, tie, клетка, t)`; `tie = next(itertools.count())` — чтобы при равных f не сравнивать клетки;
- `parent` — словарь {(клетка, t): предок}; `closed` — множество раскрытых (клетка, t);
- при извлечении: проверка цели (с учётом 1.2), затем, если t < max_t, генерация потомков из `successors`, проверка ограничений.

Проверка: `python -m unittest tests.test_pr4.Step1STAStar -v`.

### Шаг 2. Приоритетное планирование

Реализуйте `prioritized_planning`: накапливайте `path_constraints(путь, horizon)` всех уже спланированных агентов и передавайте в A* `max_t = horizon`. Возвращайте пути в **исходной** нумерации агентов, даже если порядок другой.

Проверка: `python -m unittest tests.test_pr4.Step2Prioritized -v`. Разберите в отчёте `test_incompleteness`: почему в коридоре из 4 клеток нет решения при порядке [0, 1] и есть ли оно вообще.

### Шаг 3. Первый конфликт

Реализуйте `first_conflict` — порядок проверки задан в строке документации, от него зависит ветвление CBS и тесты. Не забудьте, что после конца пути агент стоит на последней клетке (`at`), и что ожидание на месте — не обмен местами (`ua != wa`).

### Шаг 4. CBS

Реализуйте `cbs` по справке 1.4. Ограничения храните списком `frozenset` по агентам: потомок получает новый список, в котором заменён один элемент. Лимит `max_nodes` — число раскрытых узлов верхнего уровня.

Проверка: `python -m unittest tests.test_pr4.Step4CBS -v`. Тест `test_optimal_vs_bruteforce_order` сравнивает CBS со всеми 24 порядками приоритетного планирования для 4 агентов: CBS не может быть хуже лучшего из них.

**В отчёт:** нарисуйте дерево ограничений CBS для примера `test_solves_incomplete_case` (две строки карты) — узлы, конфликты, ограничения, стоимости.

### Шаг 5. Граф зависимостей

Реализуйте `action_dependencies`.

1. `actions[i] = compress(paths[i])`.
2. Для каждого агента — список визитов: (клетка, момент входа, номер действия, которым агент из неё выходит, или `None`). Первый визит — стартовая клетка с моментом 0.
3. Для каждого действия (i, k), входящего в клетку w в момент tᵢ: для всех j ≠ i и всех визитов j в w с моментом входа меньше tᵢ и существующим выходом — зависимость от (j, выход).

Проверка: `python -m unittest tests.test_pr4 -v`. Тест `test_delays_never_collide` исполняет 5 планов CBS с вероятностью задержки 0,3.

## 5. Webots

```bash
python webots/run.py run pr4_warehouse --seed <номер бригады>
python webots/run.py show pr4_warehouse --seed <номер бригады>
```

**Что происходит.** `run.py` решает CBS для 6 роботов со случайными стартами и целями (зерно — ваше) и записывает план в `webots/plans/pr4_warehouse.json`. Каждый e-puck знает весь план, строит граф зависимостей и 15 раз в секунду рассылает по радио свой прогресс — число выполненных действий. Робот начинает действие «въехать в клетку», когда из радиосообщений следует, что все зависимые действия других роботов выполнены; иначе стоит в центре текущей клетки. Действие выполнено, когда робот в 2 см от центра новой клетки.

**Итог** — `reports/webots/pr4_warehouse.json`: `arrival_time` — когда все роботы оказались у своих целей; `min_distance` — наименьшее расстояние между центрами роботов; `close_approaches` — касания.

**В отчёт:** план (рисунок клеток и путей), траектории из CSV, сравнение `arrival_time` с длительностью плана × время проезда клетки (0,25 м при 0,1 м/с) — откуда разница; наименьшая дистанция против размера клетки.

## 7. Типовые ошибки

| Симптом | Причина |
|---|---|
| `test_goal_blocked_later` падает | цель объявляется достигнутой без проверки будущих ограничений на клетку цели |
| A* не завершается | нет горизонта `max_t` или повторное добавление уже раскрытых (клетка, t) |
| CBS даёт решение с конфликтом | `first_conflict` не учитывает стоянку на цели |
| CBS очень медленный уже на 4 агентах | перепланируются все агенты в каждом узле или ограничения копируются как `set`, а не `frozenset` |
| `test_delays_never_collide` иногда падает | в зависимостях учтены только визиты со строго меньшим моментом входа не во всех местах, или забыт стартовый визит (момент 0) |
| Webots: роботы стоят и не двигаются | граф зависимостей содержит цикл — проверьте шаг 5 на плане из `webots/plans` |

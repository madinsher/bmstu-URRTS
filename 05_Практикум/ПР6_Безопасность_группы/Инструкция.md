## 1. Справка

### 1.1. Барьерная функция

Безопасное множество задано неравенством h(x) ≥ 0. Для пары роботов-интеграторов (ṗ = u)

h = ‖pᵢ − pⱼ‖² − d²,  h ≥ 0 ⇔ расстояние не меньше d.

Если во все моменты выполнено ḣ ≥ −γh (γ > 0), то h(t) ≥ h(0)·e^{−γt} ≥ 0: система из безопасного множества не выходит (лемма сравнения). Условие разрешает приближаться к границе, но тем медленнее, чем ближе граница, — «мягкий тормоз», а не стена.

**Линейное ограничение на скорость.** ḣ = 2(pᵢ − pⱼ)ᵀ(uᵢ − uⱼ). Если оба робота соблюдают правило и делят ответственность поровну:

2(pᵢ − pⱼ)ᵀ uᵢ ≥ −γh/2,  то есть aᵀuᵢ ≥ b, a = 2(pᵢ − pⱼ), b = −γh/2.

Сумма двух таких неравенств (для i и для j) даёт ḣ ≥ −γh. Ограничение линейно по uᵢ — это и делает фильтр быстрым.

### 1.2. Безопасный фильтр

Регулятор (к цели, формация, покрытие — любой) даёт номинальную скорость u_nom. Фильтр решает

min ‖u − u_nom‖²  при  aₖᵀu ≥ bₖ для всех соседей,  |u| ≤ v_max.

На плоскости задача решается точно без библиотек: оптимум лежит на пересечении не более чем двух активных ограничений. Кандидаты — u_nom (нет активных), проекция u_nom на каждую прямую aₖᵀu = bₖ (одно активное), точка пересечения каждой пары прямых (два активных). Из допустимых кандидатов берём ближайший к u_nom. Ограничение |u| ≤ v_max заменено вписанным многоугольником — тоже линейные ограничения.

Если допустимых кандидатов нет, возвращаем ноль: при h ≥ 0 у всех соседей b ≤ 0, и нулевая скорость удовлетворяет всем парным ограничениям и ограничению скорости.

### 1.3. Взаимная блокировка

Фильтр гарантирует безопасность, но не прогресс. При симметричном обмене местами роботы приходят в точку, где номинальные скорости направлены «сквозь» соседей, а фильтр оставляет только ноль, — **равновесие фильтра** (тупик). Правило «держись правее»: если робот не продвигается к цели, номинальная скорость поворачивается на −45° для всех роботов одинаково. **Гистерезис**: после срабатывания правило держится hold_steps шагов, иначе робот, сдвинувшийся вбок, на следующем шаге «забывает» о тупике и возвращается в него.

### 1.4. Устаревшие данные

Сосед i слышал j последний раз age секунд назад. За это время j мог сместиться на r = v_max,j · age в любую сторону и мог не соблюдать своё ограничение (связь потеряна — возможно, он и не знает об i). Поэтому:

- дистанция увеличивается: d′ = d + r, h′ = ‖pᵢ − pⱼ‖² − d′²;
- ответственность полная, и худшее движение соседа компенсируется: 2(pᵢ − pⱼ)ᵀuᵢ ≥ −γh′ + 2‖pᵢ − pⱼ‖·v_max,j.

Последнее слагаемое — наибольшее значение −2(pᵢ − pⱼ)ᵀuⱼ при |uⱼ| ≤ v_max,j.

### 1.5. Где гарантия кончается

Вывод 1.1 предполагает: модель ṗ = u точна; управление непрерывно; позиции соседей точны и свежи. У e-puck: неголономный привод (скорость «по направлению к» исполняется только после разворота; вынесенная точка ≠ центр робота); управление с тактом 64 мс; задержка радио на один такт. Каждое нарушение уменьшает реальную дистанцию относительно d. Это не повод отказаться от метода, а повод знать запас.

## 5. Webots

```bash
python webots/run.py run pr6_swap --seed <номер бригады>
python webots/run.py run pr6_swap_mute --seed <номер бригады>
python webots/run.py show pr6_swap --seed <номер бригады>
```

**Что происходит.** 8 e-puck на окружности радиуса 0,6 м (старты сдвинуты зерном бригады на ±2 см) меняются местами через центр. Каждый робот 15 раз в секунду рассылает позицию; соседи, услышанные за последние 0,2 с, дают `pair_constraint` с d = 0,12 м и γ = 2; более старые (до 10 с) — `stale_constraint`. Номинальная скорость — `unstuck_nominal`, ограничение 0,1 м/с. В `pr6_swap_mute` робот 0 с 3-й по 40-ю секунду не передаёт свою позицию (сам соседей слышит).

**Итог** — `reports/webots/pr6_swap*.json`: `min_distance` — наименьшее расстояние между **центрами** роботов; `close_approaches` — сближения центров ближе диаметра e-puck 0,074 м (касания); `arrival_time` — когда все оказались в 3 см от целей.

**В отчёт:** траектории, дистанция до ближайшего соседа во времени для каждого робота (по CSV), сравнение `min_distance` с d = 0,12 м и оценка вклада причин из 1.5; что изменилось в `pr6_swap_mute` и почему безопасность сохранилась.

## 7. Типовые ошибки

| Симптом | Причина |
|---|---|
| `test_matches_bruteforce` падает на отдельных наборах | не рассмотрены пересечения пар прямых или неверный знак проекции |
| роботы проходят сквозь друг друга | знак a: нужно pᵢ − pⱼ (от соседа), а не pⱼ − pᵢ |
| Э1 идёт десятки минут | `safe_velocity` с циклами Python по парам ограничений |
| с правилом тупика роботы кружат и не прибывают | условие по модулю скорости, а не по проекции на цель; или нет гистерезиса |
| `test_evades_uncooperative_neighbour` падает | нет запаса v_max·age или слагаемого худшего движения соседа |

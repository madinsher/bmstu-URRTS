## 1. Справка

**Назначение** (§10.2). N роботов, M задач, стоимость Cᵢⱼ; каждому роботу — не больше одной задачи. Оптимум находит венгерский алгоритм за O(N³). **Жадное назначение** — брать пару с наименьшей стоимостью среди свободных — за O(N²M) и без гарантии качества: если C₀₀ = 1, C₀₁ = 2, C₁₀ = 1,1, C₁₁ = 10, жадность берёт пару (0, 0) за 1 и вынуждена отдать роботу 1 задачу 1 за 10 — итого 11 против оптимальных 3,1.

**SSI — последовательный одиночный аукцион** (Koenig, Tovey, Lagoudakis и др., 2006). У робота маршрут из нескольких задач. В каждом раунде каждый робот ставит на каждую свободную задачу **приращение** длины своего маршрута при лучшей вставке; выигрывает наименьшая ставка раунда. Для критерия MiniSum SSI даёт решение не хуже удвоенного оптимума (на метрических задачах). Раундов — M, ставок — N · (M + (M−1) + … + 1).

**CBBA — консенсусный аукцион пакетов** (Choi, Brunet, How, 2009; §10.4). Децентрализованный: каждый агент знает только соседей по связи. Агент i хранит:

- b — пакет: задачи в порядке добавления;
- p — маршрут: те же задачи в порядке объезда;
- y — вектор известных выигрышных ставок по всем задачам;
- z — вектор известных победителей (−1 — нет).

**Фаза 1 — пакет.** Пока пакет не полон: для каждой задачи вне маршрута вычислить предельную выгоду cⱼ — наибольший прирост оценки маршрута при вставке; допустимы только cⱼ > yⱼ (перебить известного победителя); взять задачу с наибольшей cⱼ.

**Фаза 2 — консенсус.** Для каждой задачи агент принимает наибольшую ставку среди себя и соседей (синхронно — по значениям на начало фазы). Если агент потерял задачу из своего пакета, он освобождает её **и все задачи, добавленные после неё**: их ставки были посчитаны как приращения к маршруту, в котором потерянная задача была, и стали неверными.

**Оценка маршрута** — Σⱼ Rⱼ λ^{tⱼ}: награда дисконтируется временем прибытия. Такая оценка обладает свойством убывающей предельной выгоды — добавление задачи не увеличивает ценность остальных. При этом свойстве CBBA сходится к бесконфликтному распределению не более чем за M·D итераций (D — диаметр графа связи) и гарантирует не менее 50 % оптимума.

## 3. Базовый маршрут

### Шаг 1. Жадное назначение

Реализуйте `greedy_assignment`. Порядок при равных стоимостях — меньший номер робота, затем задачи: удобно брать `min` по кортежам `(C[i, j], i, j)`. Матрица может быть прямоугольной.

Проверка: `python -m unittest tests.test_pr3.Step1Assignment -v`.

### Шаг 2. SSI

Реализуйте `best_insertion` и `ssi_auction`.

- В `best_insertion` перебираются позиции 0 … len(route) включительно; при равном приросте — меньшая позиция (сравнение со строгим допуском `inc < best − 1e-12`).
- В раунде `ssi_auction` все ставки считаются по маршрутам **на начало раунда**; вставка — только у победителя, после перебора.
- Счётчик ставок — одна ставка на пару «робот — свободная задача» в каждом раунде.

Проверка: `python -m unittest tests.test_pr3.Step2SSI -v`. Тест `test_ssi_close_to_optimum_small` сравнивает с полным перебором.

### Шаг 3. CBBA: построение пакета

Реализуйте `cbba_build_bundle` по справке. Детали, которые проверяют тесты:

- задачи, уже стоящие в маршруте, не рассматриваются;
- `gain > agent.y[j] + 1e-12` — строго больше известной ставки;
- при выборе задачи — наибольшая выгода, при равенстве меньший номер;
- `y[j] = выгода`, `z[j] = agent.idx`, задача в конец `bundle`, в `path` — на лучшую позицию.

**В отчёт:** вручную посчитайте первый пакет для робота в (0; 0), задач в (1; 0), (2; 0), (50; 0) с наградами 10, λ = 0,95, вместимость 2 — и сверьте с тестом `test_single_agent_takes_best_tasks`.

### Шаг 4. CBBA: консенсус

Реализуйте `cbba_consensus`.

1. Сначала снимите копии `Y = [a.y.copy()]`, `Z = [a.z.copy()]` для всех агентов.
2. Для агента i и задачи j выберите лучшую пару (y, z) среди i и соседей по копиям: большая ставка; при равенстве (допуск 1e-12) — меньший номер победителя; победитель −1 не выигрывает никогда.
3. Освобождение: первая задача пакета с `z[j] ≠ i`; она и все следующие удаляются из `bundle` и `path`; для следующих, у которых `z[j] == i`, сбросить `y = 0`, `z = −1`.
4. Вернуть `True`, если что-либо изменилось.

Проверка: `python -m unittest tests.test_pr3 -v`. Тесты `Step4Consensus` прогоняют CBBA на полном графе и на пути из 4 агентов.

**Самопроверка устойчивости.** Прогоните 200 случайных задач разного размера и топологий и убедитесь, что `is_conflict_free` всегда истинно и итераций меньше 200. Если хоть раз нет — ошибка в синхронности или в освобождении.

## 7. Типовые ошибки

| Симптом | Причина |
|---|---|
| `test_every_task_once`: число ставок не совпадает | ставки считаются только для победившего робота или для всех задач, а не свободных |
| CBBA на пути не сходится за 200 итераций | асинхронное обновление в консенсусе или неверное освобождение |

| `test_does_not_outbid_better_known_bid` падает | сравнение `>=` вместо строгого `>` |

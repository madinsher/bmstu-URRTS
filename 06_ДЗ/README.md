# Домашнее задание УРРТС

Групповой проект **«Многороботный склад»**: группа роботов сама делит поток заказов, сама разводит движение и продолжает работу при отказе робота. Выполняется бригадой 2–3 человека (той же, что в практикуме) в течение семестра, четырьмя этапами.

| Документ | Что внутри |
|---|---|
| [Задание](Задание.md) | задача, уровни управления, этапы и сроки, варианты, требования Р1–Р6, задания со звёздочкой, что сдать, вопросы к защите |
| [Инструкция, этапы 1–3](Инструкция.md) | архитектура и интерфейсы, пошаговый маршрут по коду, серия прогонов, типовые ошибки |
| [Инструкция, этап 4](Инструкция_Webots_Nav2.md) | перенос в Webots с Nav2: что добавляется, подготовка, запуск, что измерить |
| [Шаблон отчёта](Шаблон_отчёта.md) ([DOCX](Шаблон_отчёта.docx)) | разделы отчёта, таблицы метрик, проверка требований |
| [Пример отчёта по этапам 1–2](Пример_отчёта_этапы_1-2.md) | образец полноты: как выглядят разделы, числа и объяснения |
| [`code`](code) | рабочее пространство ROS 2: симулятор склада, флот, сцена Webots, тесты ядер |

## Как это связано с практикумом

Практикум даёт алгоритмы по отдельности, домашнее задание собирает их в систему:

| Из практикума | Куда идёт в проекте |
|---|---|
| ПР3 (аукционы, CBBA) | логический уровень: кто берёт заказ, `cbba_core` |
| ПР4 (планы и их исполнение, граф зависимостей) | тактический уровень: резервирование клеток, `traffic_core` |
| ПР6 (барьерные функции, устаревшие данные) | защитный слой (★4) и рассуждения о безопасности при потере связи |
| ПР1 (связность графа, консенсус) | объяснение, почему при малой дальности радио CBBA даёт двойные закрепления |

## Порядок работы

1. Бригада работает в **своём репозитории** (том же, что и практикум), в каталоге `hw` — копия `code`. Теги по этапам: `hw1`, `hw2`, `hw3`, `hw4`.
2. Числа в отчёте получаются командами из приложения к отчёту на коде с тега. Каждая конфигурация — **не меньше трёх зёрен**.
3. Защита — по этапам: к контрольным неделям из задания бригада показывает артефакт этапа; итоговая защита — по всему проекту и отчёту.

## Оценивание

| Оценка | Что для неё нужно |
|---|---|
| зачтено («удовлетворительно») | этапы 1–3 выполнены, требования Р1–Р6 проверены, отчёт принят, ответы уровня A |
| «хорошо» | то же + этап 4 (перенос в Webots) и исследовательский вопрос варианта, ответы уровня B |
| «отлично» | то же + не менее двух заданий со звёздочкой и ответы уровня C |
